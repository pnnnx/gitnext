# A/B: агент с gitnext и без

## Подготовка (один раз)

```sh
cd ~/Developer/gitnext
cargo install --path crates/gitnext-cli        # свежий gitnext
bash integrations/ab/setup.sh                  # ~/Developer/ab/without и ~/Developer/ab/with
```

Обе папки — копии loca из последнего коммита с одним и тем же подложенным багом.
В `with` дополнительно `gitnext init` + `gitnext setup claude --hooks`.

## Вариант через чат (Claude в приложении)

В чате агент работает с папкой через приложение Claude на Mac, а gitnext подключается
к приложению как локальный MCP-сервер. Он общий для всех чатов, поэтому плечи идут по очереди:
сначала без gitnext, потом с ним.

**Чат 1 — без gitnext.** Убедитесь, что в настройках приложения нет сервера `gitnext`.
Новый чат → подключить папку `~/Developer/ab/without` → вставить промпт ниже.

**Чат 2 — с gitnext.**
1. Откройте `~/Library/Application Support/Claude/claude_desktop_config.json`
   (Claude → Settings → Developer → Edit Config) и добавьте сервер
   (путь к gitnext — полный: приложение не видит PATH из терминала):
   ```json
   {
     "mcpServers": {
       "gitnext": {
         "command": "/Users/pnnnx/.cargo/bin/gitnext",
         "args": ["-C", "/Users/pnnnx/Developer/ab/with", "mcp"]
       }
     }
   }
   ```
   Если в файле уже есть `mcpServers`, добавьте только блок `"gitnext": {…}`.
2. Перезапустите приложение Claude полностью (Cmd+Q).
3. Новый чат → подключить папку `~/Developer/ab/with` → вставить тот же промпт.
   В начало промпта для этого чата допишите одну строку:
   `Для навигации по коду есть инструменты gitnext (MCP) — используй их, если они удобнее.`
   Без неё агент в чате может их не заметить; в Claude Code эту роль играет блок в CLAUDE.md.

После теста уберите `gitnext` из конфига или поменяйте путь в `-C` на нужный проект.

**Что сравнить:** верность ответа на вопрос 1, `verify.sh` (запустить в терминале Mac),
время, число вызовов инструментов в логе чата. Токены в чате видно хуже, чем в Claude Code:
в конце каждого чата можно попросить «explain usage» — объяснить, куда ушли токены сессии,
если этот навык у вас есть. В чате 2 после теста — `cd ~/Developer/ab/with && gitnext journal`:
что агент вызывал из gitnext и сколько это сэкономило.

## Запуск в Claude Code (терминал)

1. Новый терминал → `cd ~/Developer/ab/without` → `claude` → вставить промпт ниже.
2. Новый терминал → `cd ~/Developer/ab/with` → `claude` → разрешить MCP-сервер `gitnext`, когда спросит → вставить **тот же** промпт.
3. Модель одна и та же в обеих сессиях (`/model`), ничего не подсказывать по ходу; на вопросы о разрешениях отвечать одинаково.
4. В конце каждой сессии: `/cost` (токены и стоимость), записать время; затем `bash ~/Developer/gitnext/integrations/ab/verify.sh ~/Developer/ab/<with|without>`.

## Ответ на вопрос 1 (для проверки, агенту не показывать)

- `loca/agent.py`, `Agent.__init__`: при `lean_tools` (по умолчанию) видимы только `MAIN_CORE`
  (или `CODE_CORE` у субагента) из `loca/tools/__init__.py`, остальные собраны в каталог
  инструмента `load_tools` (`LoadTools`, `loca/tools/agentic.py`), который модель вызывает, чтобы их включить.
- `Agent.visible` решает, попадает ли инструмент в схемы; `Agent.execute`: если модель вызвала
  скрытый, но существующий инструмент, он выполняется и включается (`_activate`);
  несуществующий — ошибка «Unknown tool … Available tools: …».
